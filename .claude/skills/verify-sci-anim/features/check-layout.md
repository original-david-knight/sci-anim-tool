# Check a layout

`sci_anim check-layout <scene file>` is the layout check. It reads the stage in the middle and at the end of every step, at the start, middle and end of every animation's span, and at every frame time of each follow's span, and prints each layout fault a line: objects the frame cuts off, text overlaps, text too small or too faint, objects in a reserved region, and more. It writes `stages.txt`, what shows at each checked scene time in words, plus contact sheets of the step times and a full-size frame per tile. Exit 0 means no fault, 1 means it printed one, and 2 means it could not check, with the JSON error report on stderr and nothing on stdout.

## Sub-features

- `layout-pass` prints `No problem at any of N checked scene times.` and exits 0 for a good lesson.
- `layout-problem` prints each layout fault at its checked scene times and exits 1.
- `layout-stages` writes `stages.txt`, every shown object at each checked scene time.
- `layout-sheet` writes `contact-sheet-<n>.png` with 16 tiles a page and `frame-<nnn>.png` per tile. `--no-sheet` skips both.
- `layout-reserve` reports every shown object in a `--reserve X0,Y0,X1,Y1` region, a molecule by each shown ball whose disc reaches into it, and draws the region magenta on the sheet. `--reserve-exempt <id>` lets one object sit there.
- `layout-reserve-span` holds a `--reserve X0,Y0,X1,Y1@START-END` region only from scene time START to END: it reports a shown object there at checked scene times inside the span, an object still fading among them, and none outside it, and outlines the region only on the sheet tiles inside the span, on any page.
- `layout-ends-only` checks only step ends with `--ends-only`: no step middles, animation spans, or frame times of follows and simulations.
- `layout-follow` checks every frame time of each follow's and each simulation's span, once however many follows and simulations hold it, reports a fault there over the run of frame times it lasts, and keeps those frame times out of `stages.txt` and the contact sheet.
- `layout-pattern` checks a text beside a `pattern` against each shown copy's box, a reserved region against each copy, and a text's contrast against the copy, solid or sphere behind it. `patterns.md` drives it.
- `layout-faded-contrast` judges a text's contrast at its object opacity, its color mixed toward what is behind it in linear light as the frame shows it, at checked scene times where no fade or follow of its opacity is playing: a text faded to 0.2 and held is reported, one mid-fade is not, and one at opacity 0 is not judged.
- `layout-never-shows` reports an object that a create, write, morph or reaction makes but that is declared at opacity 0 and never faded in, at the end of the first animation that makes it.
- `layout-transparent` prints `Contrast unverified` for each text on a transparent background, and `No verified problem` in place of `No problem`.
- `layout-touching-atoms` at each step's end, reports two shown atoms with no bond between them, in one molecule or two, whose balls rest less than 0.35 angstroms apart, since they read as bonded.
- `layout-covered-atoms` reports a text that covers atoms of a molecule beside it when the disc a shown atom's ball shows on the frame, of its `ball_radius`, reaches the text's box, even with the atom's center outside the box. sci_anim 0.10.0 and earlier tested the center only.
- `layout-scene-times` writes every scene time in its fault lines and `stages.txt` so that `inspect --scene-time` and `frame --scene-time` take it back: six significant digits, or more where six would round past the scene's end.
- `layout-cannot-check` exits 2 with the error report on stderr and empty stdout for a scene file with a scene error, a reserved region outside the frame, a span with END before START or outside the scene, or a bad flag.

## How to get to it (user POV)

- Run `sci_anim check-layout <scene file> --out <folder>`. The sci-anim skill tells agents to run it before every render. `sci_anim --version` names 0.2.0 or later.

## Driving it with the run helper

The run helper keeps its stdout as `<check>.stdout`, since it prints lines, not a report.

Preconditions:

- Baseline preconditions from the README hold, with `RUN` set. ffmpeg is on PATH for the contact sheet.

- **Pass.** `$SKILL/scripts/run "$RUN" layout-pass check-layout skills/sci-anim/examples/derivative.json --out "$RUN/layout" --ends-only`. Exit `0`. `layout-pass.stdout` starts with `No problem at any of 22 checked scene times.`, then gives the path of `stages.txt`, the paths of `contact-sheet-1.png` and `contact-sheet-2.png`, and the folder of the full-size tiles. `$RUN/layout` has `frame-000.png` to `frame-021.png`.
- **Read the stages.** `head -40 "$RUN/layout/stages.txt"` names each checked scene time and the object ids that show, in words. It matches the contact sheet. View `contact-sheet-1.png`.
- **Problem.** Move the heading off the frame: `jq '.objects.heading.position[0] = 20' skills/sci-anim/examples/derivative.json > "$RUN/work/off.json"`. Run `$SKILL/scripts/run "$RUN" layout-problem check-layout "$RUN/work/off.json" --ends-only --out "$RUN/layout-bad"`. Exit `1`. The stdout starts with `t=1.5 to 37.1 (end of step 0 to end of step 21, 22 checks): "heading" is cut off by the frame`, one line for the run of scene times where it shows. `inspect --scene-time 37.1` takes its end back, since step ends are kept to the nanosecond and the lesson lasts 37.1 seconds, not the float sum of its steps.
- **Reserved region.** `$SKILL/scripts/run "$RUN" layout-reserve check-layout skills/sci-anim/examples/derivative.json --ends-only --reserve 0,900,1920,1080 --out "$RUN/layout-reserve"`. ## Gotchas

- `--out` defaults to a folder next to the scene file. Always pass `--out` into `$RUN`, or it writes into the repo.
- A pass covers only the checked scene times, not every frame between them.
- The contact sheet draws a 4K frame per tile, and ffmpeg tiles them. `--no-sheet` is faster when you only need the faults.
